# pagination

Надстройка над цепочкой генерации: как списочный запрос превращается в постраничный. `query.sql` и `.proto` для него пишет **SG Buddy** (https://github.com/konstantin-suspitsyn/sg_buddy) — постраничность включается флагом у выборки. Го-слои остаются на конвейере репозитория.

Три инструкции по шагам конвейера, выполняются по порядку:

- `documentation/dev_instructions/crud/pagination_sql.md` — контракт сортировки и пара запросов в `query.sql`
- `documentation/dev_instructions/crud/pagination_proto.md` — сообщения и RPC
- `documentation/dev_instructions/crud/pagination_go.md` — четыре слоя Go и правки конвейера

Вход задаётся один раз, в настройках схемы: у выборки включается признак постраничности и отмечаются колонки сортировки. Новых имён пагинация не заводит — выборка `GetAliases` остаётся собой и просто получает параметры страницы.

## Два запроса на список

| Запрос | Тип | Что делает |
| --- | --- | --- |
| `Get<имя выборки>` | `:many` | одна страница: `ORDER BY` + `LIMIT`/`OFFSET` |
| `Count<имя выборки>` | `:one` | общее число строк и общее число страниц |

Счётчик считает страницы сам — `ceil(count(*) / размер страницы)`, — поэтому в Go арифметики пагинации нет. Собственного RPC у счётчика нет: его дёргает сервис перед запросом страницы. Параметры страницы называются `@page_limit` и `@page_offset`.

## Сортировка

`ORDER BY` у списочной выборки есть всегда, даже когда не отмечено ничего: без него Postgres волен вернуть строки в любом порядке, и страницы начинают то повторять строки, то терять их.

Обязательные колонки дают простой список (`ORDER BY alias.name, alias.id`). Необязательные становятся булевыми параметрами `@order_by_<колонка>::boolean` и собираются в один `CASE` с обязательным `ELSE`:

```sql
ORDER BY
    CASE WHEN @order_by_name::boolean = true THEN alias.name
         ELSE alias.id END
```

Без `ELSE` `CASE` вернул бы `NULL` и порядок пропал бы совсем. Ветки обязаны быть одного типа — Postgres не выполнит запрос, где смешались `character varying` и `bigint`; программа проверяет это сама и пишет в список проблем.

## Ответ

Записи и счётчики едут плоско в одном сообщении, общего `Pagination` на все домены нет:

```proto
message GetAliasesResponse {
  repeated Alias rows = 1;
  int64 total_rows = 2;
  int64 total_pages = 3;
}
```

## Осторожно

Конвейер Go-слоёв пагинацию пока не умеет: `resolve.py` требует на таблицу ровно восемь стандартных запросов плюс известные ему выборки, и парный `Count<имя>` роняет разбор, а у постраничного ответа три поля вместо одного. Правки в `resolve.py` и `gen.py` описаны в третьей инструкции и делаются один раз, до первой таблицы.

`query.sql` и `.proto` руками не правятся — следующее сохранение в SG Buddy перезапишет их целиком.
