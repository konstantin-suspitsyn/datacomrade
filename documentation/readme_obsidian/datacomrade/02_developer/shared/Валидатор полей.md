# Валидатор полей

Объект для проверки типов и размеров полей при создании и обновлении сущностей. Живёт в общем модуле, чтобы им пользовались все микросервисы.

- Пакет: `github.com/konstantin-suspitsyn/datacomrade/shared/pkg/validator`
- Исходники: `shared/pkg/validator`

Проверки выполняются **до похода в базу**: клиент получает понятный список того, что сломалось, вместо ошибки драйвера Postgres.

## Быстрый старт

```go
import "github.com/konstantin-suspitsyn/datacomrade/shared/pkg/validator"

func (s *tableService) Create(ctx context.Context, in *tablesv1.CreateTableRequest) (*tablesv1.Table, error) {
    v := validator.New()

    v.StringVarchar("name", in.GetName(), 128)               // varchar(128) NOT NULL
    v.StringVarchar("description", in.GetDescription(), 2000) // varchar(2000) NOT NULL
    v.Int64ID("schema_id", in.GetSchemaId())
    v.Int64ID("table_type_id", in.GetTableTypeId())
    v.Int64ID("domain_id", in.GetDomainId())
    v.Int64ID("user_id", in.GetUserId())

    if v.HasErrors() {
        return nil, status.Error(codes.InvalidArgument, v.Err().Error())
    }

    // ...
}
```

Границы длин берутся из миграции таблицы — см. [[dc.table_cat]].

## Что на выходе

Из проверки получаем две вещи.

**1. Мапа «поле → список ошибок»**

```go
v.Errors()
// map[string][]string{
//     "name":        {"поле обязательно для заполнения"},
//     "description": {"длина не должна превышать 2000 символов (сейчас 2431)"},
//     "schema_id":   {"значение должно быть больше нуля (сейчас 0)"},
// }
```

`Errors()` возвращает **копию**: изменение результата не влияет на валидатор.

**2. Наличие или отсутствие ошибок**

```go
v.Valid()      // true, если ошибок нет
v.HasErrors()  // обратная сторона Valid()
```

## Методы объекта

| Метод | Что делает |
| --- | --- |
| `New()` | Создаёт пустой валидатор |
| `Valid() bool` | Ошибок нет |
| `HasErrors() bool` | Ошибки есть |
| `Errors() map[string][]string` | Копия мапы «поле → ошибки» |
| `FieldErrors(field) []string` | Ошибки одного поля |
| `FieldValid(field) bool` | У поля нет ошибок |
| `Fields() []string` | Отсортированный список полей с ошибками |
| `Count() int` | Общее количество ошибок |
| `AddError(field, message)` | Своя ошибка вручную, дубликаты не добавляются |
| `Check(ok bool, field, message) bool` | Своя проверка, которой нет среди готовых |
| `Merge(prefix, other)` | Переносит ошибки другого валидатора (вложенные сущности) |
| `Reset()` | Очищает объект для переиспользования |
| `Err() error` | `*ValidationError`, если ошибки есть, иначе `nil` |

`Err()` удобно пробрасывать из сервисного слоя наверх — `ValidationError.Error()` собирает детерминированную строку вида `валидация не пройдена: description: ...; name: ...` (поля в алфавитном порядке), а `ValidationError.Errors` отдаёт ту же мапу для ответа клиенту по полям.

## Проверки по типам

Каждая проверка — отдельная функция, возвращает `bool`. Файлы пакета разбиты по типу поля.

### Строки — `strings.go`

| Функция | Проверяет |
| --- | --- |
| `StringRequired(field, value)` | Не пусто и не одни пробелы |
| `StringMaxLen(field, value, max)` | Верхняя граница длины |
| `StringMinLen(field, value, min)` | Нижняя граница длины |
| `StringLenBetween(field, value, min, max)` | Длина в диапазоне |
| `StringExactLen(field, value, length)` | Точная длина |
| `StringVarchar(field, value, max)` | `varchar(max) NOT NULL`: обязательно + длина |
| `StringOptionalVarchar(field, value, max)` | `varchar(max)`, пустая строка разрешена |
| `StringIn(field, value, allowed...)` | Значение из списка |
| `StringMatches(field, value, rx, hint)` | Регулярное выражение, `hint` — описание формата для сообщения |
| `StringEmail(field, value)` | Похоже на email (`EmailRX`) |
| `StringIdentifier(field, value)` | Имя объекта БД: латиница, цифры, `_`, первый символ не цифра (`IdentifierRX`) |
| `StringNoSpaces(field, value)` | Нет пробельных символов |
| `StringTrimmed(field, value)` | Не начинается и не заканчивается пробелом |

`StringVarchar` — основная рабочая функция для колонок каталога.

### Числа — `numbers.go`

Методы для типов, которые реально приходят из sqlc и protobuf:

| Функция | Проверяет |
| --- | --- |
| `Int64ID(field, value)` | Первичный или внешний ключ `int8`: больше нуля |
| `Int64Required(field, value)` | Не ноль |
| `Int64Positive` / `Int64Min` / `Int64Max` / `Int64Between` / `Int64In` | Знак, границы, список |
| `Int64FitsInt32(field, value)` | `int64` из proto влезает в колонку `int4` |
| `Int32Required` / `Int32Positive` / `Int32Min` / `Int32Max` / `Int32Between` / `Int32In` | То же для `int32` |
| `Float64Positive` / `Float64Min` / `Float64Max` / `Float64Between` | Границы, попутно проверяют конечность |
| `Float64Finite(field, value)` | Не `NaN` и не бесконечность |

Универсальные проверки сделаны пакетными функциями с дженериками — методы в Go не могут иметь собственных параметров типа:

```go
validator.NumberMin(v, "port", port, 1)
validator.NumberBetween(v, "weight", weight, 0, 100)
validator.NumberIn(v, "type_id", typeID, 1, 2, 3)
validator.NumberPositive(v, "size", size)
validator.NumberNegative(v, "delta", delta)
validator.NumberRequired(v, "user_id", userID)
```

Работают с любым числовым типом (`Number`: все `int*`, `uint*`, `float*`).

### Время — `time.go`

| Функция | Проверяет |
| --- | --- |
| `TimeRequired(field, value)` | Дата заполнена (не нулевая) |
| `TimeAfter(field, value, after)` | Строго позже границы |
| `TimeBefore(field, value, before)` | Строго раньше границы |
| `TimeBetween(field, value, from, to)` | В диапазоне включительно |
| `TimeNotInFuture(field, value)` | Не позже текущего момента |
| `TimeNotInPast(field, value)` | Не раньше текущего момента |

Формат дат в сообщениях задаётся переменной `TimeLayout` (по умолчанию `2006-01-02 15:04:05`).

### Булевы значения — `bool.go`

`BoolTrue(field, value)`, `BoolFalse(field, value)`.

### Слайсы — `slices.go`

Дженерики, вызываются как пакетные функции:

| Функция | Проверяет |
| --- | --- |
| `SliceRequired(v, field, values)` | Список не пустой |
| `SliceMinLen(v, field, values, min)` | Минимум элементов |
| `SliceMaxLen(v, field, values, max)` | Максимум элементов |
| `SliceLenBetween(v, field, values, min, max)` | Количество в диапазоне |
| `SliceUnique(v, field, values)` | Без повторов (`comparable`) |
| `SliceEach(v, field, values, check)` | Прогоняет проверку по каждому элементу |

### Необязательные поля — `optional.go`

`nil` проходит проверку, заполненный указатель проверяется.

```go
v.OptionalStringVarchar("description", in.Description, 2000)
v.OptionalInt64ID("alias_id", in.AliasId)

validator.Optional(v, "description", in.Description, func(v *validator.Validator, field, value string) bool {
    return v.StringLenBetween(field, value, 10, 2000)
})
```

## Вложенные сущности

Таблица с колонками, домен со списком ролей — ошибки вложенных объектов складываются в тот же результат с составным именем поля.

```go
for i, column := range in.GetColumns() {
    inner := validator.New()
    inner.StringVarchar("name", column.GetName(), 128)
    inner.Int64ID("column_type_id", column.GetColumnTypeId())

    v.Merge(fmt.Sprintf("columns.%d", i), inner)
}
// ошибки лягут в "columns.0.name", "columns.1.column_type_id" и т.д.
```

Через `SliceEach` короче, когда проверка одна на все элементы:

```go
validator.SliceEach(v, "columns", in.GetColumns(), func(v *validator.Validator, field string, c *tablesv1.Column) bool {
    return v.StringVarchar(field+".name", c.GetName(), 128)
})
```

## Соответствие типов БД и проверок

| Колонка в схеме `dc` | Проверка |
| --- | --- |
| `varchar(n) NOT NULL` | `StringVarchar(field, value, n)` |
| `varchar(n)` nullable | `OptionalStringVarchar(field, ptr, n)` |
| `int8` — PK/FK | `Int64ID(field, value)` |
| `int4` из proto `int64` | `Int64FitsInt32(field, value)` |
| `bool` | `BoolTrue` / `BoolFalse`, если значение задано жёстко |
| `timestamp` | `TimeRequired`, `TimeNotInFuture` |

Границы `n` берутся из миграций — см. [[README]] по схеме `dc` и [[Goose]].

## Особенности реализации

**Длина считается в символах, а не в байтах.** Используется `utf8.RuneCountInString`, как в `varchar(n)` в PostgreSQL. Иначе описание на кириллице ложно падало бы примерно на половине допустимой длины.

**Проверки возвращают `bool`.** Можно связывать цепочкой и не сыпать дублирующие ошибки на заведомо пустое поле:

```go
if v.StringRequired("name", in.Name) {
    v.StringIdentifier("name", in.Name)
}
```

**Дубликаты сообщений не копятся.** Одинаковое сообщение для одного поля добавляется один раз.

**Нулевое значение пригодно к использованию.** `var v validator.Validator` работает — внутренняя мапа создаётся лениво. `New()` предпочтительнее.

**Объект не потокобезопасен.** Один валидатор живёт в рамках проверки одной сущности, в один запрос. Делить его между горутинами нельзя.

## Сообщения об ошибках

Все тексты собраны в `messages.go` как переменные пакета (`MsgRequired`, `MsgMaxLen`, `MsgNumberPositive`, ...). По умолчанию русские. Подменять можно только на старте приложения, до начала валидации — синхронизации у них нет.

```go
validator.MsgRequired = "field is required"
```
