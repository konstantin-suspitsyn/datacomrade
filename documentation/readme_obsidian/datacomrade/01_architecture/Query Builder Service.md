# Query Builder Service

Stateless-сервис без собственной базы. Превращает выбор пользователя в готовый параметризованный SQL.

## Вход

Выбранные колонки (включая вычисления), фильтры, группировки, сортировка, пагинация + идентификатор пользователя и его роли, проброшенные [[API Gateway]].

## Алгоритм

1. Резолвит колонки через [[Metadata Service]] и **проверяет каждую запрошенную таблицу против эффективных прав пользователя**. Это защита от подмены запроса на клиенте: знание имени таблицы не даёт к ней доступа. См. [[Разграничение доступа]].
2. Проверяет допустимость каждой агрегации: тип вычисления должен поддерживаться целевой базой ([[dc.database_calculation]]) и быть разрешён для конкретной колонки ([[dc.following_calculation]]).
3. Строит диалект-независимый AST запроса.
4. Рендерит AST в SQL под конкретный диалект — см. [[Поддерживаемые СУБД]]. Значения только параметризуются, конкатенация строк не допускается.
5. Возвращает SQL + параметры + идентификатор целевой базы.

## Почему инъекции здесь структурно уже

Все имена таблиц, колонок и выражений берутся исключительно из каталога [[Metadata Service]] (белый список), а не из свободного текста пользователя. Пользователь передаёт идентификаторы объектов каталога, а не SQL-фрагменты. Это стоит зафиксировать как свойство архитектуры и не полагаться на одну лишь параметризацию — но и не ослаблять параметризацию, потому что значения фильтров приходят от пользователя как есть.

## Библиотеки

`go-sqlbuilder` покрывает нужные диалекты, включая ClickHouse и Oracle. Но оконные функции, пагинация, кавычки идентификаторов и особенности ClickHouse (`FINAL`, `dictGet`, приблизительные агрегации) потребуют собственного слоя адаптеров поверх библиотеки.
