# Мониторинг

Стек: OpenTelemetry SDK в сервисах → OTel Collector → Prometheus (метрики) + Tempo/Jaeger (трейсы) + Loki (логи, см. [[Логирование]]). Просмотр — Grafana.

Один коллектор вместо прямых экспортов из каждого сервиса даёт единое место для сэмплирования, ретраев и смены бэкенда.

## Метрики

**Базовые (RED) для каждого сервиса** — число запросов, доля ошибок, длительность по перцентилям (p50/p95/p99), отдельно по gRPC-методу.

**Продуктовые, специфичные для datacomrade:**

| Метрика | Зачем |
| --- | --- |
| `query_build_duration_seconds` | Не деградирует ли сборка SQL при росте каталога |
| `query_exec_duration_seconds{db_type}` | Разрез по типу СУБД — ClickHouse и Oracle ведут себя по-разному |
| `query_rows_returned` (гистограмма) | Ловим выгрузки-монстры |
| `query_limit_hits_total{reason}` | Как часто упираемся в timeout / max_rows: лимиты душат пользователей или защищают базы |
| `permission_denied_total` | Всплеск — либо кто-то перебирает доступы, либо права настроены неверно |
| `cache_hits_total` / `cache_misses_total{key_type}` | Оправдан ли Redis, не сломалась ли инвалидация ([[Кеширование Redis]]) |
| `db_pool_in_use` / `db_pool_waiting{db}` | Ранний признак исчерпания коннектов к целевой базе |

## Трейсы

Сквозной трейс Gateway → Metadata → Builder → Executor → целевая БД. Спан выполнения запроса должен нести атрибуты: тип СУБД, идентификатор базы, число строк, флаг попадания в кеш — тогда «почему этот отчёт строится 40 секунд» отвечается за один клик, без чтения логов.

`trace_id` в трейсах и в логах — один и тот же (см. пробел с контекстом в [[Логирование]]).

## Здоровье

`/health` (живость) и `/ready` (готовность) на каждом сервисе. Для [[Query Execution Service]] readiness должен учитывать доступность пулов к целевым базам, но **не должен** валить весь сервис из-за одной недоступной целевой БД — иначе отвалившийся Oracle уронит отчёты по Postgres. Правильно: сервис жив, конкретный источник помечен деградированным.

## Алерты (минимум)

- p99 выполнения запросов выше порога, раздельно по типу СУБД.
- Рост доли ошибок gRPC выше 1–2% за 5 минут.
- `db_pool_waiting` устойчиво > 0 — пул исчерпан.
- Обвал `cache_hits_total` — сломалась инвалидация или Redis недоступен.
- Всплеск `permission_denied_total`.

## Docker-compose

Инфраструктура наблюдаемости (Collector, Prometheus, Grafana, Loki, Tempo) — кандидат в `deploy/compose/core`, который сейчас содержит только placeholder-сервис. Это общий для всех микросервисов слой, в отличие от `deploy/compose/datacatalogue`.
