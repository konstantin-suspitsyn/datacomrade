# Дорожная карта

## Сначала — исправления в схеме

Пункты 1–3 из [[Замечания к реализации]] лучше закрыть до того, как в каталоге появятся данные: уникальность имени колонки, уникальность имени таблицы и граф связей для JOIN. Первые два — миграции на пару строк сейчас и болезненная переливка данных потом.

## MVP

- [[API Gateway]] (`shepherd`): валидация токенов Keycloak по JWKS, RBAC `Admin`/`Reader`/`Writer`, CORS, автосоздание пользователя в [[Metadata Service]], REST-контракт OpenAPI/Swagger.
- [[Metadata Service]] — читающий API каталога с учётом прав (админская часть уже частично есть).
- [[Query Builder Service]] — одна таблица без join, агрегации по [[dc.database_calculation]].
- [[Query Execution Service]] — PostgreSQL и ClickHouse (два принципиально разных диалекта сразу, чтобы слой адаптеров не оказался заточен под один).
- [[Кеширование Redis]] — дерево прав и справочники.
- [[Логирование]] — экспортируемые сеттеры контекста и интерцептор с `trace_id`.
- [[Мониторинг]] — RED-метрики, `/health`, `/ready`.

## Фаза 2

- MySQL, MSSQL, Oracle.
- Многотабличные запросы по графу связей.
- Audit Service и события аудита из брокера.
- Дашборды и алерты Grafana из [[Мониторинг]].
- Права на уровне колонки, если требование подтвердится.
- История и избранные запросы, экспорт.

## Фаза 3

- Row-level security поверх текущих прав на таблицы.
- Семантический слой: именованные метрики поверх [[dc.alias]] и [[dc.group_levels]] — фактически это уже начато и просится в явную сущность.
- Планировщик отчётов.
