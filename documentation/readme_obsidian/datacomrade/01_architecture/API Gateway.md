# API Gateway

Единственный сервис, открытый наружу. REST/JSON на границе, gRPC внутрь.

## Задачи

- Валидация access-token Keycloak по JWKS (ключи кешируются, см. [[Кеширование Redis]]).
- Извлечение ролей и `sub` из claims, проброс их во внутренние вызовы через gRPC metadata.
- Грубое разграничение: административные методы `TableService` доступны только роли `admin`. Точечная проверка «какие таблицы можно» живёт в [[Query Builder Service]] — см. [[Разграничение доступа]].
- Агрегация ответов для фронтенда (BFF): экран конструктора собирает дерево доступных таблиц/полей одним вызовом.
- Rate limiting и защита от тяжёлых запросов на входе.
- Старт трейса: генерация `trace_id`, если его нет во входящем запросе — см. [[Логирование]].

## Почему проверка прав не только здесь

Gateway не знает, какие именно таблицы затрагивает конкретный запрос: он видит DTO конструктора, а не итоговый SQL. Полное разрешение прав требует резолва полей через [[Metadata Service]], поэтому вторая (основная) проверка выполняется в Builder перед сборкой SQL. Это defense in depth, а не дублирование.
