# Развертывание

## Локально

Docker Compose, структура уже заложена в репозитории:

```
deploy/
├── compose/
│   ├── core/            # общая инфраструктура (сейчас placeholder)
│   ├── keycloak/        # Keycloak + его Postgres
│   ├── redis/           # общий Redis для всех микросервисов
│   └── datacatalogue/   # Postgres для datacatalogue (Metadata Service)
└── env/                 # централизованные .env и шаблоны
```

[[API Gateway]] (`shepherd`) своей инфраструктуры не поднимает — только подключается к уже существующим Keycloak/Redis/datacatalogue, поэтому под него нет отдельной папки в `deploy/compose`. Локально запускается как обычный Go-процесс (`go run ./cmd`), как и остальные сервисы сегодня — Docker-контейнер для самого бинарника появится вместе с прод-деплоем (см. ниже).

Кандидаты в `core`: Keycloak, Redis, брокер, стек наблюдаемости (Collector, Prometheus, Grafana, Loki, Tempo). Это общие для всех микросервисов зависимости, в отличие от базы конкретного сервиса.

Env-файлы генерируются централизованно, вручную их править не нужно — см. [[Работа с env файлами]] и [[Taskdetail]] (`task env:generate`).

## Прод

Каждый сервис — независимый Deployment в Kubernetes.

| Сервис | Профиль масштабирования |
| --- | --- |
| [[API Gateway]] | По входящему RPS, за Ingress с терминацией TLS |
| [[Metadata Service]] | Читающая нагрузка, хорошо гасится кешем |
| [[Query Builder Service]] | CPU-bound, без состояния — масштабируется свободно |
| [[Query Execution Service]] | **Ограничен соединениями к целевым БД**, а не CPU |

Ключевое ограничение: `реплики × размер пула ≤ лимит соединений целевой базы`. Autoscaling Query Execution по CPU без учёта этого приведёт к исчерпанию коннектов на источнике — то есть к деградации чужих систем, а не только своей. Метрика `db_pool_waiting` из [[Мониторинг]] — сигнал, что предел близко.

Keycloak, Redis и брокер живут вне периметра масштабирования бизнес-сервисов.
