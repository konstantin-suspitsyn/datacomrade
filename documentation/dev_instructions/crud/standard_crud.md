# Генерация query.sql — SG Buddy

`query.sql` для sqlc не пишется руками и не генерируется Claude. Его делает
отдельная программа **SG Buddy** — <https://github.com/konstantin-suspitsyn/sg_buddy>.

Этот файл описывает, как ей пользоваться и какие соглашения каталога в ней
выставлять. Форма самих запросов — на стороне программы.

Первый шаг цепочки:
**этот файл** → [proto_based_on_crud.md](proto_based_on_crud.md) → [generate_gprpc_go.md](generate_gprpc_go.md).

## Инструмент

Локальная GUI-программа на Python, поднимается на своей машине:

```bash
uv run sgbuddy
```

Откроется браузер на `http://127.0.0.1:8080`; `uv run sgbuddy --native` — то же
самое отдельным окном. Работает на Windows, Linux и macOS, из зависимостей —
Python 3.11+ и `uv`.

| | |
|---|---|
| Вход | `datacatalogue/db/sqlc/<модель>/schema.sql` |
| Настройки | `schema.json` рядом со схемой |
| Выход | `query.sql` и `.proto` |

`schema.json` программа перезаписывает целиком при каждом сохранении — правки
руками в нём не живут. Он лежит в git рядом со схемой: это описание того, из
чего собран `query.sql`, и без него перегенерация начнётся с нуля.

## Что настраивается

Настройки идут деревом: **таблица → направление (`CREATE` / `READ` / `UPDATE` /
`DELETE`) → список запросов**. Внутри направления запросов может быть сколько
угодно, у каждого своё имя.

У запроса задаются:

- имя (оно же имя метода репозитория и имя RPC);
- аннотация sqlc — `:one`, `:many`, `:exec`;
- колонки и их значения: параметр `@name`, литерал (`false`, `now()`),
  подзапрос;
- условия отбора;
- постраничность и сортировка — см. [pagination_sql.md](pagination_sql.md).

## Соглашения каталога

Программа общая, а эти правила — наши; выставлять их при настройке таблицы.

Базовый набор на таблицу — восемь запросов. `<Entity>` — имя таблицы в
PascalCase единственного числа (`table_cat` → `TableCat`, `group_levels` →
`GroupLevel`), `<Entity>s` — множественное по правилам английского.

| # | Имя запроса | Аннотация | Что делает |
|---|---|---|---|
| 1 | `Get<Entity>ById` | `:one` | активная запись по id (`is_deleted = false`) |
| 2 | `Get<Entity>s` | `:many` | активные, с сортировкой |
| 3 | `GetDeleted<Entity>ById` | `:one` | удалённая запись по id (`is_deleted = true`) |
| 4 | `GetDeleted<Entity>s` | `:many` | удалённые |
| 5 | `Create<Entity>` | `:one` | вставка, `RETURNING` |
| 6 | `Update<Entity>ById` | `:one` | обновление по id, `RETURNING` |
| 7 | `Delete<Entity>ById` | `:exec` | мягкое удаление (`is_deleted = true`) |
| 8 | `Undelete<Entity>ById` | `:exec` | восстановление (`is_deleted = false`) |

Сверх восьми таблица может иметь выборки по другим колонкам. Имя определяет,
что запрос отдаёт, — генератор Go-слоёв опирается именно на него:

| Имя запроса | Аннотация | Когда |
|---|---|---|
| `Get<Entity>sBy<Fk>` | `:many` | колонка неуникальна (внешний ключ) |
| `Get<Entity>By<Column>` | `:one` | на колонке UNIQUE |

Правила заполнения колонок:

- **id** в `INSERT` не передаётся — работает `bigserial`.
- **created_at / updated_at** — значение `now()`, не параметр. При `UPDATE`,
  `Delete`, `Undelete` всегда обновляется `updated_at`.
- **is_deleted** при `INSERT` — литерал `false`.
- **Изменяемые в `UPDATE`** — все колонки, кроме `id`, `created_at`,
  `is_deleted`. `user_id` изменяемый: кто последний правил.
- **Фильтры по `is_deleted`**: выборки активных и `UPDATE` — `= false`;
  выборки удалённых — `= true`; `Delete` и `Undelete` — **без** фильтра,
  иначе восстановить запись будет нечем.
- Колонки, которой нет в таблице, в запросе просто нет — ничего не
  подставляется по аналогии с соседями.
- Зарезервированные слова программа квотирует сама.

## Колонки `*_id` через внешний id пользователя

Если у вызывающей стороны есть только внешний id пользователя
(`dc."user".external_id`, `uuid`), а не внутренний `bigint`, значением колонки
`<col>_id` задаётся подзапрос:

```sql
(SELECT u.id FROM dc."user" u WHERE u.external_id = @external_id)
```

Так сделано для `user_id` в `tables_model` и для `updated_by_id` в
`user_domain_roles`/`user_table_roles`. Применять по задаче, а не ко всем
`*_id` подряд: обычные FK на другие таблицы (`table_id`, `alias_id`)
остаются простым параметром.

Это меняет тип параметра sqlc с `int64` на `uuid.UUID` и требует поля
`<col>_external_id` (`string`) в `.proto` — см. соответствующий раздел в
[proto_based_on_crud.md](proto_based_on_crud.md).

## После генерации

```bash
task sqlc:gen
```

Проверка, что запросов столько, сколько ожидалось:

```bash
grep -c "^-- name:" datacatalogue/db/sqlc/tables_model/query.sql
```

Дальше — `.proto` ([proto_based_on_crud.md](proto_based_on_crud.md)) и Go-слои
([generate_gprpc_go.md](generate_gprpc_go.md)).

## Осторожно при перегенерации

Запросы, написанные до перехода на SG Buddy, отличаются формой: `SELECT *`
вместо явного перечня колонок и `:one` без `LIMIT 1`. Перегенерация таблицы
приводит её к форме программы — диффы будут больше, чем кажется по объёму
правки.

Если имя запроса изменилось, Go-код, который его вызывает, перестанет
компилироваться. После генерации обязательно `task sqlc:gen`, а затем полная
перегенерация слоёв по [generate_gprpc_go.md](generate_gprpc_go.md).
